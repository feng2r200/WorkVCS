# ADR-0391: Phase 4KB Session End Expectations CLI

Status: Accepted
Date: 2026-08-31

## Context

`workvcs session end` closes a Session and reports the ended lifecycle state.
Automation needs to verify the terminal Session result directly without
following up with a separate `session show` command.

## Decision

The CLI adds optional post-end expectations to `workvcs session end`:

- `--expected-session SESSION_ID`
- `--expected-lifecycle-state STATE`

The command still delegates to `Engine::end_session`. Passing checks append
`session_match_expected=true` and `lifecycle_state_match_expected=true`.
Mismatches use the existing Session validation error surface.

`session_diff_id` remains rendered output, but it is not an expectation input
in this slice because it is generated by ending the Session rather than known
before the command runs.

## Consequences

Session lifecycle closeout can now be used directly as a script-verifiable
runtime step. Expectations are evaluated after the Session is ended; mismatch
handling does not change Session lifecycle semantics, claim release behavior,
runtime Event recording, or storage schema.
