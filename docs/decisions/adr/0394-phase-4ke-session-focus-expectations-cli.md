# ADR-0394: Phase 4KE Session Focus Expectations CLI

Status: Accepted
Date: 2026-08-31

## Context

`workvcs session focus-set` and `workvcs session focus-clear` update the
focus for an active Session and render the resulting Session focus state.
Automation needs to verify that the focus write produced the intended result
without issuing a separate `session show` command.

## Decision

The CLI adds optional post-focus expectations to both `workvcs session
focus-set` and `workvcs session focus-clear`:

- `--expected-session SESSION_ID`
- `--expected-focus ENTITY_ID_OR_NONE`
- `--expected-focus-path-entries COUNT`
- `--expected-lifecycle-state STATE`

The commands still delegate to `Engine::set_session_focus` and
`Engine::clear_session_focus`. Passing checks append
`session_match_expected=true`, `focus_match_expected=true`,
`focus_path_entries_match_expected=true`, and
`lifecycle_state_match_expected=true`. Mismatches use the existing Session
validation error surface.

`occurred_at_us` remains rendered output, but it is not an expectation input
because the timestamp is generated by the focus write.

## Consequences

Session focus updates can now be used directly as script-verifiable runtime
steps. Expectations are evaluated after the focus write; mismatch handling
does not change Session lifecycle semantics, context membership, focus
semantics, runtime Event recording, or storage schema.
