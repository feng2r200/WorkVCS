# ADR-0392: Phase 4KC Session Start Expectations CLI

Status: Accepted
Date: 2026-08-31

## Context

`workvcs session start` creates a Session for a Workspace and Branch and
reports the active lifecycle state. Automation needs to verify that the
started Session is bound to the intended context without issuing a separate
`session show` command.

## Decision

The CLI adds optional post-start expectations to `workvcs session start`:

- `--expected-workspace WORKSPACE_ID`
- `--expected-branch BRANCH_ID`
- `--expected-lifecycle-state STATE`

The command still delegates to `Engine::start_session`. Passing checks append
`workspace_match_expected=true`, `branch_match_expected=true`, and
`lifecycle_state_match_expected=true`. Mismatches use the existing Session
validation error surface.

`session_id` remains rendered output, but it is not an expectation input in
this slice because it is generated by starting the Session rather than known
before the command runs.

## Consequences

Session creation can now be used directly as a script-verifiable runtime setup
step. Expectations are evaluated after the Session is started; mismatch
handling does not change Session lifecycle semantics, context membership,
claim behavior, runtime Event recording, or storage schema.
