This is a release-notes draft prepared for the current working checkout. The
`v0.1.0` tag and GitHub Release do not exist yet, and this document does not

are not part of this release scope.

## What is included

WorkVCS v0.1.0 is a bounded, local-first V1 implementation for versioning
Agent work and knowledge state. The source tree includes:

- the `workvcs` CLI and `workvcs-core` library;
- local SQLite-backed Stores, Work-State history, branching, merge, restore,
  evidence, verification, handoff, and bounded recovery workflows;
- ProjectRef v2 logical-project routing and target-neutral capture admission;
- the bundled Agent Skill under `skills/workvcs`; and
- Apache-2.0 source and Rust package licensing.

This is a preview release, not a `1.0.0` compatibility promise. The Rust
packages remain `publish = false`; this release is not a crates.io package.

## Source installation

After a separately authorized `v0.1.0` tag exists, build from the tagged source
tree with Git and Rust/Cargo:

```bash
git clone https://github.com/feng2r200/WorkVCS.git
cd WorkVCS
git checkout v0.1.0
cargo build --release --locked -p workvcs-cli
./target/release/workvcs --version
./target/release/workvcs --help
```

During review before the tag exists, use the candidate commit above instead of
`v0.1.0`. Create local configuration and bind a project as described in the
[operator quickstart and recovery guide](../operator/quickstart-and-recovery.md):

```bash
mkdir -p "$HOME/.config/workvcs"
cp config.toml.example "$HOME/.config/workvcs/config.toml"
./target/release/workvcs config show
./target/release/workvcs project ensure --cwd /path/to/project
./target/release/workvcs resume --cwd /path/to/project
```

The first release provides source and instructions only. The local packaging
helper is not a v0.1.0 distribution artifact, and no prebuilt binary is
promised.

## Supported scope and compatibility

- Rust `1.98.1` or newer, Cargo lockfile version 4, Rust edition 2024, and
  `--locked` builds are the documented source-build baseline.
- The current public CI run validates source compilation and tests on the
  x86_64 Linux `ubuntu-latest` runner. It does not validate a Linux release
  package or installation.
- The current checkout also has supplementary source-build evidence on the
  local `aarch64-apple-darwin` host; this is not a platform release matrix.
- There is no formal Windows, macOS Intel, Linux ARM64, or UEFI compatibility
  guarantee in this source-only draft. The operator guide documents that
  migration and rollback currently fail closed on non-Unix platforms.
- SQLite is built through the bundled `rusqlite` feature, reducing dependence
  on a system SQLite installation; this does not remove ordinary Rust/Cargo
  platform requirements.

## Known limitations and boundaries

The release intentionally does not provide a Git replacement or source-code
remote, cloud synchronization, hosted collaboration, Agent launching or
orchestration, transcript parsing, LLM semantic inference, GUI/TUI, background
resource watchers, or automatic re-observation. The bounded V1 scope and its
post-V1 exclusions remain in the [readiness ledger](../provenance/v1-readiness-ledger.md)
and [release gate matrix](../provenance/v1-release-gate-matrix.md).

Security fixes currently target the latest repository revision only. Users
should report vulnerabilities through the private channel described in
[`SECURITY.md`](../../SECURITY.md). Dependency scanning found no advisory for
the locked graph in the recorded RustSec snapshot, but that result is
time-bound and is not a zero-risk claim; see the
[dependency audit record](../provenance/v0.1.0-source-release-audit.md).
